# KOC Drive

Windows 트레이 앱이 워크스페이스 공유 문서함을 탐색기에 보여 줍니다. 파일은 크기만 가진 플레이스홀더로 먼저 보이고, 열 때 내용을 받습니다. 문서함 API는 [document_frontend.md](document_frontend.md)입니다.

개인 문서함, 파일을 다시 플레이스홀더로 빼기, 카카오·애플 로그인은 포함하지 않습니다.

## 유저 플로우

1. 이메일과 비밀번호로 `POST /api/v1/auth/login`에 로그인합니다. `refresh`는 Windows 자격 증명 관리자에 두고, `access`는 메모리에만 둡니다. 만료되면 `POST /api/v1/auth/refresh`로 바꿉니다. 이 응답의 `refresh`는 로그인 때와 같은 값입니다.
2. `GET /api/v1/workspace`로 워크스페이스를 고릅니다. 하나가 아니면 처음 한 번만 고르고 기억합니다.
3. `GET /api/v1/document/{workspace_id}/space`에서 `kind`가 `shared`인 문서함을 고릅니다.
4. 앱이 켜지면 `%USERPROFILE%\KOC ERP` 폴더를 만들고, 바탕화면 `KOC ERP` 바로가기로 그 폴더를 엽니다. 바로가기·알림 영역·탐색기 아이콘은 웹과 같은 KOC 원형 마크입니다. 로그인·설정·워크스페이스 창 위에는 가로 KOC 로고가 있습니다. 이미 바로가기가 있어도 아이콘은 다시 맞춥니다. 로그인한 뒤에 이 폴더를 동기화 루트로 등록합니다. 탐색기 탐색 창 이름은 KOC ERP입니다.
5. 로그인이 끝나면 바로 동기화합니다. 알림으로 진행과 완료를 알려 줍니다. 앱을 다시 열 때 로그인이 남아 있으면 같은 알림으로 바로 동기화합니다. 이후 기본 15초마다 `GET .../changes`만 따라가며, 이 주기 동기화는 알림을 띄우지 않습니다. `지금 동기화`를 누르면 다시 알려 줍니다. 간격은 설정에서 바꿉니다.
6. 파일을 열면 `POST .../file/{file_id}/sync-url`로 내용을 받아 채웁니다. 이 호출은 다운로드 이력을 남기지 않습니다.
7. 저장, 이름 변경, 삭제는 문서함 API로 올립니다. 서버가 403이면 플레이스홀더를 되돌리고 트레이에 오류를 남깁니다. 로컬 파일이 이미 없거나 서버가 404이면 그 항목을 동기화 대기열에서 빼고 알림을 반복하지 않습니다.
8. Windows에 로그인하면 앱이 다시 실행됩니다. 설정에서 끌 수 있습니다.
9. 실행하면 시계 옆 알림 영역에 아이콘이 생깁니다. Windows는 새 아이콘을 ^ 안에 넣습니다. 로그인 전이면 "로그인이 필요합니다. 시계 옆 아이콘을 눌러 주세요."라고 알려 줍니다. 아이콘을 두 번 누르면 작업 폴더가 열립니다. 로그인 전이어도 열립니다.
10. 아이콘을 오른쪽 클릭하면 맨 위에 로그인 상태가 나옵니다. 로그아웃이면 `로그인`, `작업 폴더 열기`, `업데이트 확인`, `설정`, `종료`입니다. 로그인이면 `로그아웃`, `작업 폴더 열기`, `지금 동기화`, `업데이트 확인`, `설정`, `종료`입니다. 로그인된 동안에는 로그인 항목이 없습니다. 새 버전을 나중에 설치하기로 하면 그 항목은 `업데이트 설치 (버전)`이 됩니다.
11. 앱은 켜진 뒤와 6시간마다 `GET /api/v1/drive/release`를 로그인 없이 확인합니다. 응답은 `version`, `url`, `sha256`, `notes`입니다. 배포 버전이 없으면 `version`이 빈 문자열입니다. 설정에서 자동 설치를 켜 두면 더 높은 버전을 받아 검사한 뒤 다시 시작합니다. 끄면 설치할지 묻고, 메뉴에서 나중에 설치할 수 있습니다. 지금 받은 파일이 해시와 다르면 설치하지 않습니다. 이미 실행 중인 파일이나 마지막으로 설치한 파일의 해시가 배포 파일과 같으면 다시 받지 않습니다.
12. 로그아웃하면 저장된 토큰을 지우고 탐색기 동기화를 해제합니다. 받아 둔 파일은 작업 폴더에서 지웁니다. 서버의 원본은 그대로입니다. 다시 로그인하면 파일을 다시 받습니다. 다른 프로그램이 파일을 열고 있으면 그 파일은 남을 수 있습니다.

## 충돌

로컬 해시와 서버 `content_hash`가 같으면 그대로 둡니다. 로컬이 깨끗하고 서버만 바뀌었으면 서버 내용으로 플레이스홀더를 갱신합니다. 로컬만 바뀌었으면 `POST .../file/{file_id}/upload`와 `POST .../file/{file_id}/content`로 올립니다. `base_hash`가 어긋나 409이면 서버 내용을 유지하고, 로컬 파일은 `이름 (충돌).ext`로 새 문서에 등록합니다. 오프라인에서 만든 변경은 로컬 대기열에 두었다가 연결되면 올립니다. 열기와 받기는 온라인이어야 합니다.

## 구현 체크리스트

- 코드는 `clients/koc-drive`입니다. `KocDrive.Core`는 `net8.0`이고 WSL에서 `dotnet test` 합니다.
- `KocDrive.CloudFiles`와 `KocDrive.App`은 Windows에서만 동작합니다. 탐색기 확인은 Windows 기기에서 합니다.
- 배포본은 Windows x64용 단일 실행 파일입니다. .NET을 따로 설치하지 않습니다. `make drive VERSION=1.2.0`이 그 버전을 실행 파일에 넣고 `dist/KocDrive-win-x64.zip`을 만듭니다. 번호를 생략하면 프로젝트에 적힌 버전을 씁니다. 압축을 풀면 `KOC ERP.exe`만 있습니다. 실행하면 알림 영역 아이콘이 바로 뜨고, `%LOCALAPPDATA%\KOC ERP\KOC ERP.exe`로 복사해 다음 로그인부터는 그 파일을 실행합니다. 설치 마법사는 없습니다.
- 서버 주소 기본값은 `https://kocerpbe-main.up.railway.app`입니다. 설정에서 바꿀 수 있고, 환경 변수 `KOC_API_BASE`가 있으면 그 값이 우선합니다. https만 허용하고, 이 컴퓨터의 주소만 http를 쓸 수 있습니다. 주소에 계정 정보를 넣을 수 없습니다. 실제로 쓰는 주소가 바뀌면 로그아웃되고 저장한 토큰은 지웁니다. 파일 받기와 올리기 주소도 같은 규칙을 따르며, 다른 주소로 자동 이동하지 않습니다.
- 설정은 `%LOCALAPPDATA%\KOC ERP\settings.json`에 있습니다. 서버 주소, Windows 시작 시 자동 실행, 동기화 간격, 상태 알림, 자동 업데이트를 바꿉니다. 계정, 작업 폴더, 앱 버전은 보여 주기만 합니다. 자동 업데이트 기본값은 켜짐입니다.
- 새 설치 파일은 관리자 화면의 Drive 릴리스에 `KOC ERP.exe`를 올립니다. 목록의 다운로드로 과거 버전도 받습니다. 릴리스를 삭제하면 다른 릴리스가 같은 파일을 쓰지 않을 때 S3 객체도 지웁니다. 버전은 `1.2.0` 형식이고, 현재 배포로 저장하면 이전 현재 배포는 내려갑니다. 서버에서 올릴 때는 `python manage.py publish_drive_release --file <KOC ERP.exe> --version 1.2.0 --notes "변경 내용"`입니다. 파일은 S3에 두고, 앱이 확인할 때마다 15분짜리 받기 주소를 만듭니다. 업데이터는 1.1.0부터 들어 있습니다. 그 전 실행 파일은 이 버전을 한 번 직접 전달해야 이후부터 받습니다.
- 동기화 루트 등록은 `StorageProviderSyncRootManager`, 콜백은 Cloud Files API입니다.
- 플레이스홀더 identity는 서버의 폴더 id, 파일 id입니다.
- 파일은 1바이트 이상 1GB 이하입니다. 10초 이상 걸릴 크기는 올리거나 받기 전에 알림으로 예상 시간을 알려 줍니다. 예시는 `도면.pdf 파일을 올리고 있습니다. 약 14분 걸릴 수 있습니다.`입니다. 기준은 10Mbps이고, 1GB는 약 14분입니다. 받기 주소는 최대 2시간 유지되고, 파일 전송도 그 시간을 넘기면 끊습니다.
